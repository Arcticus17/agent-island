# 首次使用没有日志时，界面不该像坏了（2026-10-30）

用户提出的问题：即便是 Claude Code / Codex 这种内置 Agent，用户也常常是**第一次**通过灵动岛使用，
此时同样没有会话与日志——上一轮只处理了"自定义 Agent 没有适配器"，没有处理"有适配器但还没有会话"。
两者在界面上长得一样：满屏"当前会话未确认"，看起来像检测失败。

## 区分三种"没有会话"

| 状态 | 判定 | 界面 |
| --- | --- | --- |
| 有适配器，跑过但当前会话无法确认 | `has_log_adapter !== false` 且快照里有候选但歧义 | 维持"无法确认当前会话"，不拿历史冒充（既有契约） |
| 有适配器，还没跑过（冷启动） | `has_log_adapter !== false` 且 `active_session == null` | 顶部一条引导 + 「在岛内启动 <Agent>」；空态降一档字重 |
| 没有适配器（Pi 等自定义 Agent） | `has_log_adapter === false` | 顶部说明"只监控进程状态"；终端启动它自己的命令（无命令时才回退 PowerShell）；更新按钮不出现 |

## 冷启动的具体行为

- 进程**没在跑**：`还没有 <Agent> 的会话。灵动岛只显示能确认身份的当前会话；在终端里跑一轮，或直接在岛内启动它。`
  + 按钮「在岛内启动 Claude Code / Codex CLI / …」（点了会打开岛内终端并启动对应 CLI）。
- 进程**在跑**：`已检测到 <Agent> 在运行，正在等它写出第一条会话记录…`（不给按钮，避免起第二个实例）。
- 自定义 Agent 永远走"只监控进程状态"分支，不会出现"在岛内启动"按钮。
- 冷启动 / 无适配器时，空态标题（"无法确认当前会话"）降到正文档字重与字号，不再像告警。

## 边界

- "在岛内启动"现在对所有岛内 Agent 可用：内置跑自己的 CLI，自定义/自动发现的跑快照里下发的 `program`；只有压根没有启动命令时才回退 PowerShell。
- 启动后到日志写出之间仍有一小段空窗，此时显示"正在等它写出第一条会话记录"。
- 冷启动引导建立在"会话只来自结构化日志"的产品契约上：没有日志就没有会话，这不是检测失败。
